# Music Doctor

- Сохранять цепочку snapshot → validate → prepare → preview → apply → status. Фактическое состояние берётся из файла, цели — из запроса v2, только apply меняет исходный файл. Music — каталог, источник дополнений и refresh, без запасного способа записи тегов.
- Сохранять фильтры CLI. --has и has.FIELD учитывают наличие в файле и в доступном Music. FIELD=music-only ищет пропуски файла, которые можно дополнить из Music. Префиксы file. и music. фиксируют источник. Unknown отличается от отсутствия. Пользовательские строки передавать как данные.
- Полный snapshot печатает сводку, прогресс в stderr и подробности в логе рядом с запросом. Параллелить чтение файлов с ограничением нагрузки и сохранять порядок треков.
- Заполнять tags из аудиофайла. Сохранять подсказки Music в необязательном music_suggestions и планировать запись только после явного переноса значения в tags. Подсказки и вложения из Music отмечать в логе. Принимать from_music в старых запросах v2 для совместимости.
- Для пакетного чтения путей Music проверять длину столбцов, уникальность и порядок ID до связывания с файлами. Неподтверждённые пути читать по ID.
- В запросе v2 поля artwork и lyrics содержат путь или состояние наличия. Только путь задаёт локальное вложение для записи. Старые запросы v2 с *_file и has остаются читаемыми.
- Закреплять TagLib 2.3.2 и utf8cpp с проверкой целостности сборки. Нативный модуль работает локально. Пользовательская поставка не требует Python, FFmpeg, Node или Homebrew.
- Не обходить хеши, проверки исходника и вложений, защиту временного файла, проверку аудиопакетов и журнал. Force включает равные цели в план, отсутствующие значения не удаляет.
- Проверять сохранность непереданных тегов и аудиоданных до атомарной замены. Удалять копии после проверки конечного файла и сохранения журнала. При неизвестном результате сохранять копию и честно указывать стадию восстановления.
- Перед обновлением Music сверять текущий путь записи по ID с проверенным путём аудиофайла. Результаты записи файла и обновления Music отражать отдельно.
- Новые пакеты используют формат v2. Старые форматы имеют только подходящие команды чтения. Актуальные примеры, справку, README и NAVIGATION обновлять вместе с контрактом.
- Проверки описаны в README. Запись в тестах выполнять на синтетических файлах/изолированных копиях. Живая проверка Music требует реального доступа к приложению и отдельной тестовой подборки. Пользовательские данные и результаты не коммитить.

- При записи ID3v2.2 планировать явную миграцию в v2.3; проверять возможность записи в prepare, преобразовывать только временную копию в apply и сравнивать нормализованные незатронутые кадры, raw-инвентарь и аудиоданные. Неизвестные кадры и неподдерживаемые флаги отклонять до сохранения плана.
