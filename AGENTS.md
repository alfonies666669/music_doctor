# Работа с Music Doctor

## Контракт

- Универсальный движок для macOS/Music и локальных незашифрованных MP3/M4A. Пользовательские ID, жанры, метаданные, обложки и тексты — во внешних данных, не в логике движка.
- Сохранять цепочку `snapshot → validate → prepare → preview → apply → status`. Только `apply` изменяет музыку; `prepare` создаёт план и локальные assets. `audit` читает JSON, `inspect` читает актуальные Music/файлы.
- `snapshot` без выходного пути — лёгкий просмотр; с путём — редактируемый запрос версии 1, сразу пригодный для `prepare`. `--show` ограничивает только вывод, не выборку.
- Запрос: `id`, `expect`, `set`/`fill`, опциональные `defaults`, обложка, lyrics, источники и `info`. `null` в `set`/`fill` не задаёт изменение; ненулевые `defaults` остаются активны. Приоритет `set → defaults → fill`. В планах `null` для записываемых полей недопустим.
- `info` — контекст экспорта, не команды записи. Старые снимки поддерживаются в `audit`; новые экспортируются в формате запроса.
- Фильтры — аргументы CLI с AND/OR/NOT; отдельный JSON-ввод фильтров удалён. Пользовательские выражения — данные, их нельзя исполнять как код.
- Альбомы, релизы, жанры и кредиты задаёт пользователь. Не добавлять поиск метаданных или подмену producer/composer внутрь движка.
- Сохранять проверки исходных данных/хешей, резервные копии, журнал частичных отказов и сверку тегов напрямую из файла. Автоотката нет. `library_playlist_id` не считать уникальным отпечатком медиатеки.

## Изменения и проверки

- Актуальная версия — `TOOL_VERSION` в `jxa.js`. Описание команд должно совпадать в `usage()` / `snapshotUsage()`, README.md, NAVIGATION.md и примерах.
- При изменении поведения/формата обновлять соответствующую документацию и обезличенные примеры; добавлять защитные тесты для существенной логики. Для правок только текста достаточно существующих проверок.
- Код разделён: `core.js` — проверка запросов/планов и выполнение; `filters.js` — разбор/отбор/сортировка; `jxa.js` — адаптер macOS/Music; `artwork.applescript` — запись обложки.
- Команды проверок приведены в README.md: четыре Node-набора, нативный тест и валидация обоих примеров. Запускать из корня проекта.
- Тестирование записи — только на изолированных копиях при соответствующем разрешении. Нативные тесты с имитацией Music не подтверждают реальную запись в медиатеку.
- Не коммитить пользовательские аудио, lyrics, обложки, запросы, планы, журналы, резервные копии и runs/. Общедоступные примеры в examples/ должны быть вымышленными.
