# Как заполнить снимок Music Doctor

[snapshot.json](snapshot.json) показывает снимок, [request.json](request.json) — запрос с выбранными изменениями.

Начни с цели. Для треков без обложек заполняй `artwork`. Если совпало несколько релизов и нужный нельзя подтвердить, оставь прежнее значение.

| Поле | Как заполнять |
|---|---|
| `tags` | Снимок подставляет теги аудиофайла. Впиши подтверждённые метаданные в нужные поля. `prepare` сравнит их с текущими тегами. |
| `artwork` | Укажи путь к JPEG или PNG, например `covers/001.jpg`. |
| `lyrics` | Укажи путь к TXT в UTF-8, например `lyrics/001.txt`. |
| `music_suggestions` | Подсказки Music для пустых тегов. Чтобы принять подсказку, перенеси значение в `tags`. |
| `path`, `sha256`, `music_ids` | Служебные значения. Сохрани их при редактировании. |

Относительные пути считаются от папки с JSON. Для `artwork` и `lyrics` строка задаёт вложение, `true` означает подтверждённое наличие без вложения, `false` — отсутствие, `null` — неизвестное состояние. Для текста из сети можно указать `lyrics_url` с HTTPS-адресом `text/plain` вместо пути к TXT.

Например, для добавления обложки положи `001.jpg` в папку `covers` рядом со снимком и замени значение `artwork` на `"covers/001.jpg"`. В `preview` для этого трека должна появиться запись `artwork`. Если ты заполнял только обложки, проверь, что в плане перечислены только они.

~~~sh
./music-tags validate runs/selected.json
./music-tags prepare runs/selected.json runs/plan.json
./music-tags preview runs/plan.json
~~~

При записи в MP3 с ID3v2.2 версия тегов переводится в v2.3. `prepare` фиксирует этот переход в плане, `preview` показывает его, а `apply` выполняет на временной копии с проверкой сохранности данных. Поле миграции в запрос вручную добавлять не нужно. Старые планы для таких файлов пересоздай.
