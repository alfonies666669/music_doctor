# Выбор треков для snapshot

Команда только читает Music. Без выходного пути — краткий просмотр в консоли; с путём — редактируемый запрос для `validate` / `prepare`.

```sh
./music-tags snapshot --artist '1.kla$ OR Czar'
./music-tags snapshot --artist '1.kla$ OR Czar' --show all
./music-tags snapshot --artist '1.kla$ OR Czar' runs/selected-v1.json
```

В консоли: количество, общая длительность, число избранных; затем артист, название, длительность, альбом, год и `fav:+/-/?`. Первые 20 строк по умолчанию. `--show N` / `all` меняет только вывод; в JSON всегда вся выборка. Без выходного пути аудиофайлы, обложки, lyrics и хеши не читаются.

## Область поиска и фильтры

Без области — вся медиатека. `--playlist "French"` ограничивает поиск одним плейлистом; его имя должно быть уникальным. `--all` явно выбирает всю медиатеку. `snapshot French` — просмотр плейлиста, `snapshot French out.json` — его экспорт. При фильтрах предпочитай явный `--playlist`; для имени плейлиста с окончанием `.json` он обязателен, иначе одиночный `.json` трактуется как выходной файл.

| Флаг | Условие |
|---|---|
| `--name`, `--title` | Название содержит текст |
| `--artist` | Поле исполнителя содержит текст, включая совместные записи |
| `--album` | Альбом содержит текст |
| `--album-artist` | Исполнитель альбома содержит текст |
| `--genre` | Жанр совпадает целиком, без поиска по подстроке |
| `--favorite true` / `false` | Избранный / не избранный трек |
| `--min-duration`, `--max-duration` | Длительность от/до включительно: секунды, `M:SS` или `H:MM:SS` |
| `--sort` | Порядок результата: `name`, `artist`, `album`, `albumArtist`, `genre`, `favorite`, `duration` |
| `--desc` | Обратная сортировка; требует `--sort` |
| `--show N` / `all` | Строки консоли: по умолчанию 20; 0 — только сводка |

Разные фильтры соединяются через **AND**. Одинаковый флаг нельзя повторять: используй выражение внутри одного аргумента. `--name` и `--title` — один фильтр. Длительность неотрицательная, минимум не больше максимума; `180.5`, `3:00`, `1:02:03` допустимы. В JSON длительность — `info.duration` в секундах, она не редактирует теги.

```sh
./music-tags snapshot --genre 'German Hip-Hop' --artist 'Bushido OR Fler'
./music-tags snapshot --playlist French --artist Leto --sort name runs/leto-v1.json
./music-tags snapshot --favorite true --min-duration 3:00 --max-duration 10:00 --sort duration --desc
```

Регистр, крайние/повторные пробелы и канонические Unicode-варианты не влияют на совпадение. `German Hip-Hop` и `German Hip Hop` — разные жанры; `Russian German Hip-Hop` не проходит по `--genre 'German Hip-Hop'`. Фильтр использует текущий тег и не определяет музыкальную принадлежность.

## AND / OR / NOT

Выражение передаётся **одним аргументом в общих кавычках**. Слова-операторы только заглавные; также доступны `&&`, `||`, `!`. Приоритет **NOT → AND → OR**; скобки меняют группировку.

| Выражение в `--artist` | Результат |
|---|---|
| `'Bushido OR Fler'` | Сольные и совместные записи обоих артистов |
| `'Bushido AND Fler'` | Оба имени встречаются в поле artist |
| `'Bushido NOT Fler'` | Bushido есть, Fler нет; равно `Bushido AND NOT Fler` |
| `'(Bushido OR Fler) AND NOT Sido'` | Любой из первых двух, без Sido |

Логика работает в `--name` / `--title`, `--artist`, `--album`, `--album-artist`, `--genre`. Для жанра каждый термин сопоставляется целиком, для остальных — по содержимому поля. Если участник фита указан только в названии, `--artist` его не найдёт. Чтобы исключить имя ещё и из названия, добавь `--name 'NOT Fler'`.

Для буквального имени с оператором или скобками внутри выражения используй внутренние двойные кавычки:

```sh
./music-tags snapshot --name '"LOVE AND WAR" OR "NOT TODAY"'
./music-tags snapshot --artist '"AK Ausserkontrolle" OR Fler'
./music-tags snapshot --name '"Song (Remix)" AND NOT Live'
```

`Or Noir`, `Not Afraid`, `Song (Part II)` без операторов ищутся буквально. `$`, точки и другие символы не являются регулярными выражениями. Одинарные внешние кавычки сохраняют `$` в `'1.kla$'`. Нельзя писать `--artist "Bushido" || "Fler"`: без общих кавычек `||` обрабатывает оболочка. После `\` для переноса команды не должно быть пробелов или комментариев.

## Экспорт и ограничения

Экспорт — запрос версии 1 с `id`, `expect`, текущими значениями `set`, пустым `fill`, местами под обложку/TXT и справочным `info`. Пропуски и `set.lyrics` — `null`. Правила заполнения и применения — [README.md](README.md); пример — [examples/snapshot.json](examples/snapshot.json). Условия поиска в JSON не сохраняются. Ввод фильтров отдельным JSON и флаги `--info` / `--lite` не поддерживаются.

Избранное читается через `favorited`, для старого Music — `loved`. Если оба недоступны, фильтрация/сортировка по избранному завершается ошибкой. Неизвестное значение — не `false`; `NOT` неизвестного остаётся неизвестным. Если всё условие осталось неизвестным, запись исключается, количество видно в консоли. При сортировке неизвестные значения остаются последними в обоих направлениях; при равенстве сохраняется исходный порядок.

Пакетное чтение проверяет порядок ID. При экспорте повторно проверяются условия отбора; ошибка чтения или переставший подходить трек блокирует сохранение, частичного запроса нет. Лёгкий просмотр может показывать облачные записи; экспорт требует доступных незашифрованных локальных MP3/M4A. Хеши аудио считаются позже, в `prepare`. Без совпадений JSON не создаётся; существующий файл не перезаписывается.

Краткая справка: `./music-tags snapshot --help`.
