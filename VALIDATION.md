# Проверка MVP 0.1.1 — 20.11.2026

Логика первоначально проверена в Linux; исправления 0.1.1 дополнительно проверены нативным osascript на Mac. Доступ среды отладки к объектам Music не подтверждён: обращение по bundle ID возвращает Application can't be found, по пути приложения — Parameter is missing. Это не приравнивается к воспроизведению полного prepare в Terminal пользователя.

Нативно пройдено 8 проверок: исходный NSNull/count воспроизведён; исправленный mkdir; JSON; запуск NSTask и stdout; SHA-256; ошибка подпроцесса; разрешение AVURLAsset и чтение настоящего Mandalorian.mp3; проверка его Title из файла. Музыкальные теги не записывались.

Выполнено:

- `node tests/core.test.js`: **21 проверка прошла**.
- `node --check core.js` и `node --check jxa.js`: синтаксис JavaScript проверен.
- `sh -n music-mvp`: синтаксис launcher проверен.
- Запуск launcher на Linux: завершился с кодом 1 и явным сообщением о необходимости macOS; изменений музыки не было.
- Пять записей пилота и их целевые значения взяты из сохранённого French-Hip-Hop-metadata-plan.md. Исходный французский документ не изменён.
- `tests/pilot-simulation.json`: все пять операций закончились `verified` **в имитации**, не на настоящих файлах.

Не проверено в этой среде:

- Разрешение macOS Automation и словарь установленного Music.
- Полное чтение/запись JXA-свойств настоящих треков после исправления.
- Загрузка обложек через штатный curl именно на Mac и AppleScript-запись картинки.
- Представление всех изменяемых ID3/MP4-тегов в AVFoundation (чтение имеющихся полей одного MP3 подтверждено).
- Поведение Music с включёнными организацией папок и Sync Library.

Следующий обязательный этап — команды doctor → prepare → preview → apply → inspect на Mac, описанные в README. Если прямое чтение тегов не подтвердит результат, операция считается незавершённой: изучить журнал, поправить адаптер, не расширять выборку.
