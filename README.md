# Music MVP 0.1.1

Небольшой инструмент для **твоих правил и выбранного списка треков**. Запускается из терминала, общается с Music через JXA/AppleScript. Не управляет мышью, не зависит от Node.js, Python, beets или сторонних библиотек. Использует штатные средства macOS: `osascript`, Foundation, AppKit, AVFoundation, `curl`, `shasum`.

**Статус 0.1.1:** 21 проверка логики прошла; на Mac дополнительно прошли 8 нативных проверок, включая воспроизведение и исправление `NSNull count`, запуск подпроцессов и чтение настоящего MP3 через AVFoundation. Полный `prepare/apply` через Music после исправления ещё не подтверждён: среда отладки не получает доступ к объектам медиатеки. Запись музыки не выполнялась.

В 0.1.1 исправлены nullable Objective-C параметры (`$()` вместо JavaScript `null`), вызовы NSTask без аргументов и получение класса AVURLAsset. Добавлены имена тегов ID3v2.2. При обновлении заменить `jxa.js`; остальные исходные файлы 0.1 совместимы. Сохранённые пользовательские планы и журналы не удалять.

После ошибки старого `prepare` повторить с новым именем вывода, например `french-plan-fixed.json`: это обойдёт возможную незавершённую папку `.assets`, не удаляя её.

## Первый запуск — пять французских треков

Распаковать архив на Mac, открыть Terminal в папке `music-mvp`. Ничего устанавливать не нужно. Если архиватор снял право запуска: `chmod +x music-mvp`.

```sh
./music-mvp doctor
./music-mvp prepare examples/french-five.json french-plan.json
./music-mvp preview french-plan.json
```

`doctor` проверяет связь с Music. macOS может один раз запросить разрешение Terminal управлять Music; приложение может запуститься. Это программный доступ, не автоматизация экрана.

`prepare` читает актуальные поля **по Persistent ID**, проверяет исполнителя и название, фиксирует контрольные суммы файлов. Для отсутствующих обложек запрашивает заранее выбранные каталожные ID и скачивает проверенные JPEG/PNG не менее 500×500. До записи проверяет совпадение артиста, названия, альбома и длительности. Совпадение не означает акустическую идентификацию. На этом этапе музыкальные поля не меняются.

После просмотра плана команда записи:

```sh
./music-mvp apply french-plan.json
```

Проверить результат отдельно:

```sh
./music-mvp inspect french-plan.json > french-result.json
```

Пилот: **Kaaris — Goulag; Kaaris — Mandalorian; Leto — Paris c'est magique; SCH — Euro; Ziak — Akimbo**. Их Persistent ID и проверенные целевые значения взяты из французского плана от 20.11.2026. Сомнительные One Shot и Facom в первый запуск не включены. Для другой медиатеки эти ID использовать нельзя.

При неудачном `prepare` исходные файлы не изменены. Могут остаться скачанные обложки в `french-plan.json.assets`; для следующей подготовки выбрать новое имя плана, например `french-plan-2.json`.

## Что именно делает MVP

- Поддерживает существующие доступные локальные **MP3/M4A** в Music; за запуск — 1–20 записей.
- Меняет название, артиста, альбом, исполнителя альбома, композитора, жанр, год, номера треков/дисков и их количество, compilation — только если эти поля явно указаны. Пилот название/артиста не меняет.
- `defaults.genre` задаёт твой жанр; индивидуальный `set.genre` имеет приоритет. Каталог жанр не перезаписывает.
- `set` означает явное целевое значение; `fill` дополняет только пустые строки/нулевые числа. В пилоте Composer дополняется только при отсутствии.
- Существующие обложки сохраняет. Добавляет только отсутствующие, без замены всей коллекции картинок.
- Не пишет оценки, избранное, счётчики, даты добавления, плейлисты или параметры воспроизведения. Не удаляет записи и не импортирует их заново.
- Проверяет исходное состояние **всей группы** до первой записи, сохраняет полные копии изменяемых аудиофайлов, ведёт журнал каждого действия. При ошибке останавливается.
- Сверяет записанные свойства Music, затем читает файл через AVFoundation. Если теги файла не подтверждены — завершает с ошибкой, даже если Music показывает нужное значение. Если AVFoundation не умеет представить конкретный тег на данной версии macOS, это тоже считается незавершённой проверкой, а не доказательством отсутствия тега.

Приложение Music может само организовывать файлы в папки после изменения альбома/артиста. Инструмент файловые пути не назначает; после записи повторно получает актуальный путь по тому же ID и заносит его в журнал. Отключить «Сохранять организацию папки медиафайлов», если перемещения со стороны Music нежелательны. Поведение Sync Library также нужно проверить на пилоте.

## Файлы после запуска

| Файл | Назначение |
|---|---|
| `french-plan.json` | Актуальные исходные значения, контрольные суммы и точные изменения |
| `french-plan.json.assets/` | Загруженные и проверенные обложки |
| `french-plan.json.backups/` | Полные оригиналы изменяемых файлов, проверенные по SHA-256 |
| `french-plan.json.journal.json` | Что пробовали записать и что подтвердилось, исходные/конечные поля, пути к копиям |

Сохранить план, журнал и копии вместе. **Автоматического отката в MVP нет.** Запись нескольких полей через Music не является транзакцией: при ошибке часть полей уже может измениться. Журнал отражает попытки и ошибку; не повторять `apply` вслепую. Для восстановления нужны и исходные поля Music из журнала, и резервные файлы; простое копирование файла обратно не гарантирует обновления базы приложения.

Если план устарел, подготовить новый. План с существующим журналом повторно не применяется. Повторная подготовка того же запроса после успешной операции должна показать отсутствие изменений. Не редактировать `before` вручную для обхода проверки; нужные целевые значения меняются в исходном запросе.

## Запрос для другой группы

Получить снимок нужного плейлиста (только чтение):

```sh
./music-mvp snapshot "French" snapshot.json
```

Из снимка взять `id`, `metadata.name`, `metadata.artist`. Создать JSON:

```json
{
  "version": 1,
  "defaults": {"genre": "French Hip-Hop"},
  "tracks": [{
    "id": "6EBE236014BCF430",
    "expect": {"name": "Mandalorian", "artist": "Kaaris"},
    "set": {"album": "2.7.0", "year": 2020, "trackNumber": 2, "trackCount": 20},
    "fill": {"composer": "KozBeatz"},
    "artwork_catalog_id": 1544794819,
    "sources": ["https://music.apple.com/fr/album/mandalorian/1544794808?i=1544794819"]
  }]
}
```

Поля `fill`, `set`, `sources`, `artwork_catalog_id` необязательны. `expect` с названием и артистом обязателен. Пример предназначен для исходной медиатеки Александра, не для произвольного компьютера. Неизвестные поля и недопустимые значения отклоняются; строки `null`, «уточнить» и пустые заглушки не записываются.

Для поиска кандидатов:

```sh
./music-mvp search "Kaaris Mandalorian"
```

Поиск выдаёт до 15 кандидатов с ID, альбомами, датами и ссылками. **MVP не выбирает релиз автоматически.** Я готовлю подтверждённый запрос, инструмент его выполняет. Это сознательная граница первого варианта: библиотечные предпочтения и неоднозначные версии не передаются общему автоподбору. Отдельные инструкции для нового чата — в `AGENT.md`.

## Ограничения 0.1.1

Нет распознавания по аудиоотпечатку, автоматического поиска продюсеров/текстов, редактирования Producer, произвольных расширенных тегов или замены существующей обложки. Composer и Producer не смешиваются: неподдерживаемый `producer` отклоняется с ошибкой. Источники Composer для пилота сохранены рядом с запросом; полнота всего авторского состава не заявляется.

Нет обещания полной независимости от Music: это выбранный встроенный механизм записи. Не редактируем бинарную базу Music. Поддержка нативных API и конкретных тегов проверяется первым запуском на Mac; если возникает ошибка, сохранить её и журнал для исправления адаптера.

## Проверка разработчиком

Только для разработки, с доступным Node.js:

```sh
node tests/core.test.js
node --check jxa.js
```

Нативная проверка без управления Music, на Mac из папки инструмента:

```sh
/usr/bin/osascript -l JavaScript tests/native.test.js "$PWD"
```

Необязательный второй аргумент — путь к MP3/M4A для проверки прямого чтения тегов. Этот тест не меняет аудиофайл.

Проверяются реальные защитные сценарии: устаревший план и файл, другая медиатека, дубликаты и общий файл у двух записей, личные жанры, нумерация, отказ резервного копирования, молча проигнорированная запись, частичная ошибка, неподтверждённые файловые теги, защита обложек и имитация пяти треков. Node нужен лишь для этих тестов, не для использования инструмента. `tests/pilot-simulation.json` — результат **имитации**, не изменения настоящей музыки.

Первый тест на Mac считается завершённым только когда: `doctor` работает; `prepare` показывает верную группу; `apply` возвращает Verified; журнал имеет `status: complete`; `inspect` подтверждает нужные поля и встроенную обложку, а плейлисты/история сохранились. При частичном результате не называть весь пилот завершённым.
