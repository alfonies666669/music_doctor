# Music Doctor

Обновляет теги, обложки и тексты песен в локальных MP3 и M4A на macOS.

**Выбрать треки → сохранить снимок → заполнить данные → посмотреть изменения → записать.**

Снимок — обычный JSON. Его можно заполнить вручную или передать на обработку вместе с вложениями. Программа сама не ищет релизы, обложки и авторов: она записывает подготовленные тобой данные.

## 1. Сделать снимок

Открой Terminal в папке Music Doctor. Для плейлиста из приложения «Музыка»:

```sh
./music-tags snapshot --playlist 'Для обработки' runs/my-batch/request.json
```

Или возьми файлы из папки:

```sh
./music-tags snapshot --folder "$HOME/Music/Incoming" --recursive --music runs/my-batch/request.json
```

`--music` связывает файлы папки с уже существующими записями в «Музыке». Если эта связь не нужна, убери флаг. Файлы в приложение автоматически не импортируются.

Получишь `request.json`, папку `request.json.assets/` с извлечёнными обложками и текстами, если они есть, и `request.json.log` с подробностями. Держи JSON и его вложения вместе. Для новой подборки используй новое имя папки вместо `my-batch`.

Если путь для JSON не указан, команда только покажет найденные треки в консоли.

## 2. Заполнить данные

Открой полученный `request.json` и измени нужные поля:

| Поле | Что с ним делать |
|---|---|
| `tags` | Исправь название, исполнителя, альбом, жанр, год, композитора или нумерацию |
| `artwork` | Укажи путь к нужному JPEG или PNG, например `covers/song.jpg` |
| `lyrics` | Укажи путь к TXT в UTF-8, например `lyrics/song.txt` |
| `music_suggestions` | Подсказки из «Музыки». Для записи перенеси выбранное значение в `tags` |
| `path`, `sha256`, `music_ids` | Сохрани как есть: они связывают изменения с исходными файлами |

Пути к картинкам и текстам считаются от папки с JSON. Файл `covers/song.jpg` в этом примере нужно положить в `runs/my-batch/covers/`.

Заполняй только подтверждённые сведения. Неизменённые значения останутся прежними; `null` не удаляет тег. Значения `true`, `false` и `null` у обложки или текста описывают наличие, отсутствие или неизвестное состояние. Для **записи** вложения нужен путь к файлу.

Сравни обезличенные [снимок](examples/snapshot.json) и [заполненный запрос](examples/request.json). Все поля и дополнительные варианты описаны в [справочнике](docs/reference.md).

## 3. Проверить изменения

```sh
./music-tags validate runs/my-batch/request.json
./music-tags prepare runs/my-batch/request.json runs/my-batch/plan.json
./music-tags preview runs/my-batch/plan.json
```

`prepare` сверит исходные файлы и соберёт план с копиями нужных вложений. Музыка на этом этапе не изменяется. В `preview` должны быть только ожидаемые изменения. Если редактировал только обложки, в плане должны быть только они.

Для старого MP3 дополнительно может появиться `ID3v2.2 → ID3v2.3`: это необходимое преобразование формата тегов при записи.

## 4. Записать

```sh
./music-tags apply runs/my-batch/plan.json
./music-tags status runs/my-batch/plan.json
```

Только `apply` меняет аудиофайлы. Он проверяет результат записи, незатронутые теги и аудиоданные. Для связанных треков затем обновляет «Музыку»; при записи обложки дополнительно назначает её через приложение.

Результаты файла и приложения отдельные: `file_status: verified` подтверждает файл, `music_artwork_status: verified` — назначение обложки в «Музыке». Если вывод содержит `Music warnings`, смотри `music_error` в результате `status`. Один только `Verified: N files` не подтверждает успешное обновление приложения.

Рядом с планом сохраняется журнал `plan.json.journal.json`. Во время записи создаётся резервная копия; после проверки файла и сохранения журнала она удаляется. При ошибке нужные для восстановления копии сохраняются, их пути указаны в журнале. Синхронизация с другими устройствами остаётся задачей приложения «Музыка».

## Если что-то изменилось или пошло не так

- Исправил запрос после `prepare` — создай план с новым именем. Старый план уже содержит прежние цели.
- Изменился исходный аудиофайл — сделай свежий снимок. Не подменяй хеш вручную.
- План завершён — повторный `apply` ничего не перезаписывает.
- Нужно намеренно повторить запись тех же значений — свежий снимок и новый `prepare … --force true`.
- Запись прервалась — сначала `status` и `inspect`, затем новый снимок по фактическому состоянию. Сохрани старый журнал и указанные копии восстановления.

```sh
./music-tags inspect runs/my-batch/plan.json
```

## Отбор и остальные команды

Можно выбирать треки по исполнителю, названию, жанру, альбому, длительности, избранному и наличию тегов:

```sh
./music-tags snapshot --genre 'Custom Hip-Hop' --has 'artwork=false' runs/covers/request.json
./music-tags snapshot --artist 'Artist A OR Artist B' --show all
./music-tags snapshot --folder "$HOME/Music/Incoming" --has 'file.composer=false'
```

`doctor` проверяет доступность файлового модуля и «Музыки». `audit request.json` перечисляет незаполненные данные в запросе; достоверность метаданных он не оценивает.

Все параметры: `./music-tags snapshot --help` и [справочник](docs/reference.md). Поддерживаются незашифрованные локальные MP3 и M4A с AAC/ALAC. Для готовой сборки не нужны Python, Node.js, FFmpeg или Homebrew.

Пользовательские подборки, планы и журналы храни в `runs/`: эта папка исключена из Git. Старые экспериментальные папки переносит туда `./scripts/tidy.sh` в исходном проекте.

Сборка, устройство проекта и тесты: [документация для разработки](docs/development.md).
