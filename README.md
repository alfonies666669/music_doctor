# Music Doctor 0.8.0

CLI `music-tags` для пакетного редактирования локальной медиатеки Music на Mac. Работает с доступными незашифрованными MP3/M4A через JXA/AppleScript, без управления экраном. Для запуска достаточно macOS и Music; Python, Node.js и сторонние пакеты не нужны.

Альбомы, жанры, кредиты, обложки и тексты готовит пользователь. Инструмент проверяет и применяет указанные данные; автоматического поиска метаданных нет.

## Быстрый старт

Открой Terminal в каталоге проекта. При первом обращении разреши Terminal управлять Music, если macOS запросит это.

```sh
./music-tags doctor
# Посмотреть выборку, ничего не сохранять:
./music-tags snapshot --artist '1.kla$ OR Czar'
# Сохранить всю выборку в редактируемый запрос:
./music-tags snapshot --artist '1.kla$ OR Czar' runs/selected-v1.json
```

Без пути к JSON — краткая сводка и первые 20 треков; `--show all` выводит все, `--show 0` оставляет сводку. Этот режим не читает аудиофайлы, обложки и lyrics и не считает хеши. Фильтры и логические выражения описаны в [NAVIGATION.md](NAVIGATION.md).

С путём к JSON — сразу формат `request.json`: заполни **тот же файл**, сохраняя `id` и `expect`. Затем:

```sh
./music-tags validate runs/selected-v1.json
./music-tags prepare runs/selected-v1.json runs/plan-v1.json
./music-tags preview runs/plan-v1.json
# После проверки изменений:
./music-tags apply runs/plan-v1.json
./music-tags status runs/plan-v1.json
```

**Только `apply` меняет музыку.** Для новых экспортов, планов и отчётов используй новые имена: существующие файлы не перезаписываются.

## Что редактировать в запросе

JSON версии 1, UTF-8; необязательное `description` — пояснение к запросу. `examples/snapshot.json` показывает результат экспорта; `examples/request.json` — минимальный запрос. ID в примерах вымышленные, перед `prepare` нужны значения из своей медиатеки.

| Поле | Назначение |
|---|---|
| `id`, `expect` | Persistent ID из 16 hex-символов, исходные название и артист. Не менять при заполнении запроса; пустое исходное значение — `""` |
| `set` | Целевые значения. Совпадающие значения пропускаются |
| `fill` | Дополнить только пустые поля |
| `defaults` | Общие целевые значения; приоритет `set` → `defaults` → `fill`. Lyrics здесь не допускаются |
| `artwork_file` | JPEG/PNG: относительный к JSON или абсолютный путь. Добавить обложку, если её нет в аудиофайле |
| `lyrics_file` / `lyrics_url` | UTF-8 TXT или прямая HTTPS-ссылка на `text/plain`. Один источник текста на трек |
| `lyrics_policy` | Для внешнего текста: `fill` по умолчанию, `replace` для замены существующего |
| `sources` | Необязательный массив HTTPS-ссылок на источники данных |
| `info` | Справка на момент экспорта: длительность, избранное, обложки и lyrics. Не задаёт изменения |

Экспорт переносит текущие значения в `set`, пропуски — в `null`. В `set`/`fill` `null` означает «не задавать изменение этим полем», а не стереть тег. При этом ненулевые `defaults` продолжают действовать. Чтобы применить общий `defaults.genre`, удали `set.genre` или замени его на `null`. Без ручных правок свежий экспорт не предлагает изменений; позже заполненные `set` остаются целевыми значениями.

Поддерживаются `name`, `artist`, `album`, `albumArtist`, `composer`, `genre`, `year`, `trackNumber`, `trackCount`, `discNumber`, `discCount`, `compilation`, `lyrics`. Числа — целые от 1 до 9999; номер трека/диска не должен превышать итоговое количество. `compilation` — boolean; строки, кроме lyrics, — до 2000 символов без управляющих знаков. Пустые строки и нули как новые значения не принимаются; неизвестные поля отклоняются. Producer отдельным полем не поддерживается; композитор и продюсер не взаимозаменяемы.

`set.lyrics` при экспорте всегда `null`: существующий текст не копируется в JSON. Укажи `lyrics_file: "lyrics/song.txt"` или текст прямо в `set.lyrics` / `fill.lyrics`, например `"First line\nSecond line"`. Ненулевые inline/file/URL-источники нельзя сочетать. Поддерживаются обычные Custom Lyrics без синхронизации; HTML-страницы и streaming-lyrics не извлекаются. URL скачивается в `prepare`, если нужен новый текст; `validate` проверяет формат URL и локальные вложения без сети.

Лимиты: 100 000 символов lyrics, 400 КБ TXT, 15 МБ JPEG/PNG. `artwork_file` также принимает объект с обязательным `path` и необязательными `sha256` (64 строчных hex-символа), `format` (`jpg`/`png`), `album`, `source_url` (HTTPS). Хеш и целевой альбом проверяются. Встроенная обложка сохраняется; при нескольких картинках в Music добавление требует ручной проверки.

## Проверка заполненности и результата

```sh
./music-tags audit runs/selected-v1.json
./music-tags audit runs/selected-v1.json runs/audit-v1.json
./music-tags inspect runs/plan-v1.json
```

`audit` читает только JSON: для нового запроса оценивает метаданные черновика, а наличие обложек/lyrics — по `info` на момент экспорта. Путь к новому TXT ещё не означает, что текст встроен в трек. Старые снимки подходят для `audit`, но для `prepare` нужен новый экспорт. Это проверка заполненности, а не правильности альбома, кредитов или картинки.

`inspect` читает актуальные сведения Music и теги файлов для ID из плана. `status` показывает журнал выполнения, а не повторную проверку медиатеки. Для новой проверки заполненности после `apply` сделай новый экспорт и `audit`.

При экспорте недоступный, облачный или защищённый выбранный трек блокирует сохранение с указанием ID; частичный запрос не создаётся. Без совпадений JSON не создаётся.

## Файлы выполнения и ошибки

`prepare` сохраняет план с исходными метаданными/хешами и каталог `plan-v1.json.assets/` с нужными обложками; тексты входят в план. `apply` проверяет исходные данные перед записью, сохраняет оригиналы в `plan-v1.json.backups/` и шаги в `plan-v1.json.journal.json`, затем сверяет результат в Music и аудиофайлах. Не редактируй и не переноси подготовленный план; ID библиотечного плейлиста сам по себе не является уникальным отпечатком медиатеки.

При ошибке выполнение останавливается; **автоотката нет**, часть полей могла измениться. Проверь `status` и журнал, затем подготовь новый план под новым именем. Завершённый неизменный план повторно не применяется. Music может перемещать файлы согласно своим настройкам.

Храни запросы и результаты в игнорируемых Git каталогах `local/` и `runs/`. Аудиофайлы, обложки, тексты, планы и резервные копии пользователя не входят в исходный код.

## Проверки для разработчика

Node.js 18+ нужен только для тестов:

```sh
node --test tests/core.test.js tests/adapter.test.js tests/filters.test.js tests/snapshot.test.js
osascript -l JavaScript tests/native.test.js "$PWD"
./music-tags validate examples/request.json
./music-tags validate examples/snapshot.json
```

Тесты не меняют музыку: нативная проверка создаёт временные файлы и использует имитацию Music. Необязательный второй аргумент native-теста — путь к MP3/M4A для прямого чтения тегов. Успех этих проверок не подтверждает реальную запись в пользовательскую медиатеку.
