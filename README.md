# Music Doctor 0.8

Для владельцев **локальной медиатеки Music на Mac**, которым нужны пакетные правки метаданных из Terminal. Поддерживаются доступные незашифрованные MP3/M4A.

**Проект устанавливается один раз.** Для новой группы передаётся новый JSON с данными и, при необходимости, папки с обложками/TXT. Правильные альбомы и кредиты готовятся отдельно; инструмент проверяет и применяет указанные значения.

## Вход

`request.json`, кодировка UTF-8. Один запрос может содержать всю группу, например 46 записей:

```json
{
  "version": 1,
  "defaults": {"genre": "My Genre"},
  "tracks": [{
    "id": "0000000000000001",
    "expect": {"name": "Example Song", "artist": "Example Artist"},
    "set": {"album": "Example Album", "year": 2024},
    "fill": {"composer": "Example Composer"},
    "artwork_file": "covers/example.jpg",
    "lyrics_file": "lyrics/example.txt"
  }]
}
```

ID и `expect` берутся из снимка **своей** медиатеки. Значения примера нужно заменить. `examples/request.json` — обезличенный пример для проверки формата, без обложек и файловых зависимостей.

| Поле | Значение |
|---|---|
| `id`, `expect` | Обязательные Persistent ID, текущее название и артист; идентифицируют запись без выделения в Music. Если поле пустое, указать `""` |
| `set` | Явно заменить указанные значения; совпадающие и `null` пропускаются |
| `fill` | Дополнить только пустые поля; имеющиеся значения сохраняются, `null` пропускается |
| `defaults` | Общие целевые значения. Приоритет: `set` → `defaults` → `fill` |
| `artwork_file` | Путь к JPEG/PNG относительно JSON. Добавляется, если картинки нет **в файле**; уже встроенная сохраняется |
| `lyrics_file` / `lyrics_url` | UTF-8 TXT или прямая HTTPS-ссылка, возвращающая `text/plain`. По умолчанию дополняет только отсутствующий текст; `lyrics_policy: "replace"` включает замену |
| `info` | Контекст на момент экспорта: длительность, избранное, наличие обложек и lyrics. Не задаёт изменения |

Поддерживаемые метаданные: `name`, `artist`, `album`, `albumArtist`, `composer`, `genre`, `year`, `trackNumber`, `trackCount`, `discNumber`, `discCount`, `compilation`, `lyrics`. Числа передаются числами, `compilation` — boolean. Неизвестные поля отклоняются.

Lyrics можно указать прямо в JSON: `"fill": {"lyrics": "First line\nSecond line"}`; для явной замены — `set.lyrics`. Выбирается один источник текста. Поддерживается обычный Custom Lyrics без синхронизации; HTML-страницы не разбираются. Лимиты: 100 000 символов текста, 400 КБ TXT, 15 МБ картинки. Для обложек рекомендуется 1000×1000.

Обложку также можно задать объектом с `path` и необязательными `sha256`, `album`, `source_url`: хеш и альбом проверяются. `sources` у трека — необязательный массив HTTPS-ссылок на источники.

## Использование

Распаковать проект, открыть Terminal в `music-tags-tool`. При первом обращении macOS может попросить разрешить Terminal управлять Music.

```sh
./music-tags doctor
./music-tags snapshot "Playlist name" runs/snapshot.json
./music-tags snapshot --artist Bushido --min-duration 3:00 --sort name runs/artist-snapshot.json
./music-tags validate ../track-data/request.json
./music-tags prepare ../track-data/request.json runs/plan.json
./music-tags preview runs/plan.json
./music-tags apply runs/plan.json
./music-tags status runs/plan.json
```

`snapshot --all` читает всю медиатеку. `validate` проверяет вход без Music; `prepare` собирает локальный план; `preview` показывает его. **Только `apply` меняет музыку.** План нельзя переносить на другой компьютер или редактировать для обхода проверки.

### Посмотреть → заполнить тот же файл

```sh
./music-tags snapshot --artist '1.kla$ OR Czar'
./music-tags snapshot --artist '1.kla$ OR Czar' --show all
./music-tags snapshot --artist '1.kla$ OR Czar' runs/klass-czar-v1.json
```

Без пути к JSON — краткий список: количество, общая длительность, число избранных, артист, название, альбом, год и длительность трека. Показываются первые 20 строк; `--show all` — все, `--show 0` — только сводка. Аудиофайлы, обложки и lyrics в лёгком режиме не читаются, хеши не считаются.

С путём к JSON сохраняется **готовый запрос формата `request.json`**. В `set` перенесены текущие значения, пропуски обозначены `null`. Исправь значения прямо здесь, сохраняя `id` и `expect`. `null` означает «оставить без изменений», пустые строки и нули для записи не допускаются. `set` имеет приоритет над `defaults`; чтобы применить общий `defaults.genre`, удали `set.genre` или поставь ему `null`.

`set.lyrics` всегда `null`, чтобы не раздувать JSON существующими текстами. Наличие текста и картинок видно в `info`; для добавления укажи относительные `lyrics_file` и `artwork_file`, например `lyrics/song.txt` и `covers/album.jpg`. `info` не задаёт изменения. Пример: `examples/snapshot.json`.

```sh
# После заполнения того же файла:
./music-tags validate runs/klass-czar-v1.json
./music-tags prepare runs/klass-czar-v1.json runs/klass-czar-plan-v1.json
./music-tags preview runs/klass-czar-plan-v1.json
# После проверки плана:
./music-tags apply runs/klass-czar-plan-v1.json
```

Экспорт включает всю выборку: `--show` ограничивает только консоль. При экспорте читаются локальные файлы выбранных треков; недоступные, облачные и защищённые записи блокируют сохранение с указанием ID. Частичный запрос не сохраняется. Без совпадений файл не создаётся. Существующий файл не перезаписывается.

Перед записью проверяются исходные данные и хеши; сохраняются оригиналы файлов и журнал. Результат сверяется в Music и файлах. Music может перемещать файлы согласно своим настройкам; плейлисты и история сохраняются.

При ошибке запись останавливается, **автоотката нет**: часть полей могла измениться. Посмотреть `status` и журнал, затем подготовить новый план под новым именем. Завершённый неизменный план повторно не применяется. Старые планы Music MVP подготовить заново.

## Проверка проекта

Разработчику с Node.js 18+: `node tests/core.test.js`, `node tests/adapter.test.js`, `node tests/snapshot.test.js`, `node tests/filters.test.js`. Нативная проверка без записи музыки: `osascript -l JavaScript tests/native.test.js "$PWD"`; второй аргумент — необязательный MP3/M4A для чтения.

Пройдены автотесты и нативная подготовка плана. Базовая запись ранее проверена на пяти MP3; запись lyrics и обложек этой сборкой ещё требует пилота. Producer, автоматический поиск метаданных и извлечение streaming-lyrics не поддерживаются.


### Снимок по жанру и проверка заполненности

```sh
./music-tags snapshot --genre "German Hip-Hop" runs/german-snapshot-v1.json
./music-tags audit runs/german-snapshot-v1.json runs/german-audit-v1.json
```

Жанр отбирается по текущему тегу всей медиатеки: регистр, крайние/повторные пробелы и канонические Unicode-варианты не важны. Остальное написание должно совпадать: `German Hip-Hop` и `German Hip Hop` — разные значения. Составные жанры не включаются по подстроке. При отсутствии совпадений файл не создаётся; проверь точное написание жанра в Music. Треки, ошибочно размеченные другим жанром или без жанра, такой фильтр не найдёт.

`audit` читает только сохранённый JSON, без обращения к Music: показывает наличие обложек в самом файле и отдельно в приложении, lyrics, пропуски метаданных и список записей для проверки. Значение `compilation=false` считается заполненным. Ошибки чтения файлов подсчитываются отдельно от отсутствующих данных. Старые снимки без признака встроенной обложки дают «unknown», а не ложное «missing». Второй аргумент audit необязателен: без него отчёт только выводится в Terminal.

Это проверка заполненности: непустой неверный альбом и неподходящая обложка сами по себе не распознаются. Исходные аудиофайлы и медиатека не изменяются. Сохраняй каждый новый снимок/отчёт под новым именем. Схема запросов и планов версии 1 сохранена; старые планы не нужно переделывать из-за этого обновления.

`audit` принимает старые снимки и новые запросы. Для запроса пропуски метаданных считаются по значениям черновика, а наличие обложек и lyrics — по `info` на момент экспорта. Добавленный путь к TXT/картинке ещё не означает, что файл встроен в музыку. Без `info` статус неизвестен. После `apply` сделай новый экспорт для актуальной проверки.


Проверки разработчика для новых команд: `node tests/snapshot.test.js`. В `examples/snapshot.json` — вымышленный редактируемый запрос для validate/audit без Music.


## Навигация снимков: фильтры и И/ИЛИ/НЕ

Версия 0.5 добавляет фильтры по названию, исполнителю, альбому, жанру, избранному и диапазону длительности; их можно сочетать. `--sort` и `--desc` задают порядок записей только в снимке. Разные флаги соединяются через И; внутри текстовых аргументов можно писать AND/OR/NOT. Логика вынесена в независимый `filters.js`. Подробная справка и примеры — [NAVIGATION.md](NAVIGATION.md), краткая — `./music-tags snapshot --help`. Схема запросов и планов записи сохранена.


## Выражения прямо в консоли

`--artist 'Bushido OR Fler'` выбирает сольные и совместные записи обоих артистов. `--artist 'Bushido NOT Fler'` (равнозначно AND NOT) оставляет Bushido и исключает Fler. Работают AND/OR/NOT, &&/||/!, скобки; приоритет NOT → AND → OR. Всё выражение заключай в общие кавычки, иначе логические символы обработает оболочка. Операторы-слова распознаются только заглавными. Для буквального названия с AND/OR/NOT используй внутренние двойные кавычки. Примеры — [NAVIGATION.md](NAVIGATION.md), справка — `./music-tags snapshot --help`. Снимок только читает медиатеку.
