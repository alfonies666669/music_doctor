# Справочник Music Doctor

Основной порядок работы — в [README](../README.md).

## Команды

| Команда | Результат |
|---|---|
| `snapshot [отбор] [request.json]` | Без пути — список в консоли; с путём — редактируемый снимок и вложения |
| `validate request.json` | Проверка формата запроса и указанных локальных вложений |
| `prepare request.json plan.json [--force true\|false]` | Проверка исходников и сохранение плана; по умолчанию только отличия |
| `preview plan.json` | Изменения из плана без записи |
| `apply plan.json` | Запись и проверка файлов, обновление связанных записей Music, журнал |
| `status plan.json` | Журнал и проверка текущего состояния файлов |
| `inspect request-or-plan.json` | Чтение фактических тегов аудиофайлов |
| `audit request.json [report.json]` | Незаполненные поля запроса, отдельно неизвестное состояние вложений |
| `doctor` | Версия программы, файловый модуль и доступность Music |
| `--version` | Версия программы |

Команды чтения не изменяют аудиофайлы. `snapshot`, `prepare` и `audit` с выходным путём создают свои JSON и вспомогательные файлы. Существующие запросы и планы не перезаписываются.

## Выбор треков

Источник по умолчанию — вся медиатека Music. `--playlist 'Название'` ограничивает её одним плейлистом, `--all` явно выбирает всю медиатеку. `--folder PATH` выбирает папку; `--recursive` включает подпапки, а `--music` связывает найденные файлы с каталогом Music. Фильтр по избранному в папке требует `--music`.

| Параметр | Сравнение |
|---|---|
| `--name`, `--title` | Название содержит текст |
| `--artist` | Исполнитель содержит текст, включая совместные записи |
| `--album` | Альбом содержит текст |
| `--album-artist` | Исполнитель альбома содержит текст |
| `--genre` | Жанр совпадает целиком |
| `--favorite true\|false` | Избранное в Music |
| `--min-duration`, `--max-duration` | Включительные границы: секунды, `M:SS` или `H:MM:SS` |
| `--has 'FIELD=true\|false'` | Наличие данных; подробнее ниже |
| `--sort FIELD [--desc]` | Сортировка; неизвестные значения идут в конце |
| `--show N\|all` | Число строк в консоли; состав сохраняемого JSON не меняется |

Разные параметры соединяются через AND. Внутри текстового аргумента поддержаны `AND`, `OR`, `NOT`, скобки и символы `&&`, `||`, `!`. Приоритет: NOT, затем AND, затем OR. Регистр имён не важен; слова операторов пишутся заглавными.

```sh
./music-tags snapshot --artist 'Artist A OR Artist B' runs/two-artists/request.json
./music-tags snapshot --artist 'Artist A AND NOT Artist B'
./music-tags snapshot --name '"Rock AND Roll"' --max-duration 4:00
```

Заключай всё выражение в один аргумент оболочки. Для буквального текста, содержащего слова операторов, используй внутренние двойные кавычки. Одинарные внешние кавычки также сохраняют `$` в имени исполнителя.

Для сортировки доступны `name`, `artist`, `album`, `albumArtist`, `genre`, `favorite`, `duration` и `has.FIELD` с вариантами источника.

### Проверка наличия

`FIELD`: `name`, `artist`, `album`, `albumArtist`, `composer`, `genre`, `year`, `trackNumber`, `trackCount`, `discNumber`, `discCount`, `compilation`, `artwork`, `lyrics`.

| Выражение | Значение |
|---|---|
| `artwork=false` | В доступных источниках обложка подтверждённо отсутствует |
| `file.artwork=false` | Встроенной обложки в аудиофайле нет |
| `music.artwork=true` | Music сообщает о наличии обложки |
| `artwork=music-only` | В Music обложка есть, а в файле отсутствует |
| `composer=false OR artwork=false` | Нет композитора или обложки |

При доступном Music поле без префикса учитывает оба источника; для обычной папки — файл. Неизвестное состояние отличается от отсутствия и не становится совпадением после `NOT`. Причины исключения треков попадают в лог снимка.

## Запрос JSON v2

Снимок уже имеет нужный формат. Вручную создавай его только при наличии достоверного пути и актуального SHA-256.

| Поле | Назначение |
|---|---|
| `version` | `2` |
| `tracks[].path`, `sha256` | Абсолютный путь к аудио и хеш на момент снимка |
| `tracks[].music_ids` | Связанные Persistent IDs Music; необязательны для файлового режима |
| `tracks[].tags` | Желаемые значения тегов; снимок начинает с прочитанного состояния файла |
| `tracks[].artwork`, `lyrics` | Путь к вложению либо состояние наличия |
| `tracks[].music_suggestions` | Подсказки Music, которые сами по себе не записываются |
| `defaults` | Общие значения тегов для записей без индивидуального значения |
| `tracks[].fill` | Заполнение только отсутствующих в файле тегов |

Приоритет целей: ненулевое значение `tags` → `defaults` → `fill` при отсутствии тега. Для общего изменения через `defaults` удали индивидуальное значение соответствующего поля или поставь ему `null`. В обычном режиме записываются только отличия от файла.

Строковые теги: `name`, `artist`, `album`, `albumArtist`, `composer`, `genre`. Допустимы строка или непустой список строк. Числовые: `year`, `trackNumber`, `trackCount`, `discNumber`, `discCount` — целые от 1 до 9999. `compilation` принимает `true` или `false`. `null` не задаёт удаление. Пустые строки и неоднозначные исходные значения не перезаписываются молча.

### Обложки и тексты

| Значение | Смысл |
|---|---|
| Строка с путём | Использовать содержимое файла для записи |
| `true` | Наличие подтверждено, но вложение не задано |
| `false` | Подтверждено отсутствие |
| `null` | Наличие неизвестно |

Обложка: JPEG/PNG до 15 МБ. Текст: UTF-8 TXT до 400 КБ и 100 000 символов, без HTML. В начале текста удаляется BOM, переводы строк нормализуются. Для получения текста по сети вместо `lyrics` можно задать `lyrics_url`: HTTPS, ответ `text/plain`, до 30 секунд. Ссылки на обычные страницы с текстом песни не подходят.

Абсолютные пути поддерживаются. Относительные считаются от JSON запроса. `prepare` сохраняет нужные вложения в `plan.json.assets/` и фиксирует их хеши: изменение исходного запроса не меняет готовый план.

Ранние варианты v2 с `has`, `artwork_file`, `lyrics_file`, `from_music` остаются читаемыми. Новые снимки используют поля из таблицы выше. Старые документы v1 поддерживают только подходящие команды чтения; для новой записи нужен снимок v2.

## План, журнал и восстановление

План содержит проверенные цели, хеш и физическую идентичность исходного файла, состояние до записи и замороженные вложения. Его не следует редактировать вручную. `--force true` включает совпадающие цели, сохраняя все проверки.

После записи Music может переименовать файл. Текущий подтверждённый путь сохраняется в `resolved_path`, конечный хеш — в `after_sha256`, идентичность — в `after_identity`. Эти поля используют `inspect` и `status`. После явного назначения обложки Music файл проверяется повторно, а его конечные хеш и идентичность обновляются.

`status: complete` означает, что обработка файлов завершена. Обновление приложения оценивается по `music_status`, обложка — по `music_artwork_status`. Для ошибок сохраняется `music_error` с причиной из системного скрипта.

При отказе записи журнал фиксирует стадию и пути копий. Если файл уже заменён, сохраняется `file_written`; потеря пути не выдаётся за отсутствие записи. Автоматического повтора или отката нет. После проверки журнала и фактических данных нужен новый снимок и новый план.

Не удаляй указанные в незавершённых журналах копии. Архивные завершённые планы служат историей; после переноса папки готовь новые планы из свежих снимков.
