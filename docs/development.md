# Разработка и проверки

Пользовательский сценарий описан в [README](../README.md); контракт команд и JSON — в [справочнике](reference.md).

## Структура

| Файл или папка | Ответственность |
|---|---|
| `music-tags` | Запуск на macOS |
| `jxa.js` | CLI, системные операции и адаптер приложения Music |
| `core.js` | Контракт v2, вычисление целей, превью и общие функции; без I/O |
| `filters.js` | Разбор, проверка, вычисление и сортировка фильтров |
| `file-commands.js` | Снимок, подготовка плана, запись, журнал и проверка файлов |
| `legacy.js` | Только чтение документов v1; старого движка записи нет |
| `native/` | Исходники модуля TagLib, сборка и упаковка |
| `bin/music-tags-file` | Готовый файловый модуль для установленной платформы |
| `*.applescript` | Извлечение и явное назначение обложки Music; значения передаются аргументами |
| `tests/`, `scripts/check.sh` | Автоматические проверки на синтетических файлах |
| `examples/`, `docs/` | Обезличенные JSON и документация |
| `runs/` | Пользовательские подборки и история; исключены из Git |
| `build/`, `dist/` | Генерируемые файлы сборки и архивы; исключены из Git |

## Сборка

Для разработки нужны macOS 13+, Apple Command Line Tools, CMake 3.24+, Node.js и FFmpeg. Для готовой пользовательской сборки эти инструменты не требуются.

```sh
cmake -S native -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build build --parallel
cp build/bin/music-tags-file bin/music-tags-file
```

CMake загружает официальный TagLib 2.3.2 и проверяет SHA-256 архива, включающего utf8cpp 4.2.0. Связывание статическое, zlib и фреймворки Apple системные. Версия нативного модуля — отдельная версия реализации; она не обязана совпадать с версией CLI.

## Полная проверка

```sh
./scripts/check.sh
```

Команда проверяет синтаксис shell/JS/AppleScript, выполняет Node-тесты последовательно и проверки настоящего моста Foundation/JXA. Последовательный запуск нужен из-за общей блокировки `apply`. Нативный модуль должен быть собран в `build/bin/` и установлен в `bin/`.

Проверяются запросы и планы, фильтры, пакетное чтение каталога, запись MP3 v2.2/v2.3/v2.4 и M4A AAC/ALAC, сохранность аудио и незатронутых тегов, атрибуты и ACL, миграция старых тегов, устаревшие планы, ошибки и резервные копии, переименование файлов Music и отдельный шаг назначения обложки.

Все записи выполняются на временных синтетических файлах. Адаптер Music в сквозных тестах заменён заглушкой; эти тесты не подтверждают отображение обложек в живом приложении или синхронизацию между устройствами. Отдельно проверяются компиляция настоящих AppleScript и чтение/сохранение JPEG/PNG без событий Music. Последний тест явно пропускается, если хост блокирует файловые команды Standard Additions; остальные ошибки считаются отказом теста.

## Правила записи

1. Фактические теги читаются из файла; каталог Music даёт выбор треков и необязательные подсказки.
2. `prepare` сверяет SHA-256 исходников, фиксирует идентичность и замораживает вложения. Запись в музыку не выполняется.
3. `apply` проверяет план и вложения, создаёт копию исходника и рабочую копию рядом с файлом.
4. Запись идёт во временную копию. Сравниваются цели, незатронутые данные, кадры/атомы метаданных и аудиопакеты; восстанавливаются расширенные атрибуты и ACL.
5. Проверенная копия атомарно заменяет исходник. Журнал сразу фиксирует факт записи и идентичность нового файла.
6. Для связанных Music IDs сверяется путь и обновляется приложение. Обложка назначается явно, читается обратно, затем снова проверяется аудиофайл.
7. Только после проверки и сохранения журнала рабочие аудиокопии удаляются. При неоднозначном результате копии сохраняются.

Ошибки файла и Music не объединяются в один успешный статус. Диагностика подпроцессов сохраняет конкретный stderr, а не только код выхода. Ни `force`, ни недоступность Music не отключают проверки файла.

## Поставка

```sh
./native/package.sh
```

Архив в `dist/` содержит CLI, нативный модуль, системные скрипты, примеры, документацию и лицензии. Тесты, сборочный кеш, планы и пользовательские данные в него не включаются.

## Уборка старых подборок

```sh
./scripts/tidy.sh
```

Скрипт переносит старые корневые папки `music-artwork-apply-*` и `french-run*` в отдельный каталог внутри `runs/archive/`, затем убирает эти пользовательские данные из индекса Git. Содержимое сохраняется. Повторный запуск ничего не дублирует.

Исходные аудиофайлы и резервные копии `.music-doctor-*` в медиатеке не затрагиваются. `runs/` остаётся рабочим местом для новых подборок. Архивные журналы сохраняются как история; планы со старыми абсолютными путями повторно не запускаются.
